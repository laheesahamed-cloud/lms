# CSS Cleanup Plan — Dead-Code Removal

**Goal:** Remove all genuinely-dead CSS from `frontend/src`. **Strictly deletion-only** —
no new selectors, properties, files, or dependencies are introduced.

**Status:** Phase 1 done (6 full rules). Phase 2 = this pass (dead tokens in grouped selectors).

---

## Scope

- **In scope:** hand-authored CSS under `frontend/src/**`.
- **Out of scope (do not touch):**
  - `frontend/dist/**` — committed build output, regenerated by `npm run build`.
  - `ios/`, `android/`, `dist-capacitor/` — untracked build cache.
  - Tailwind utilities / `tailwind.config.js` keyframes & animations (`animate-*`).
  - Any live class — including dynamically composed ones (see "Confirmed live").

## How "dead" was confirmed (no guessing)

A class is dead only if **all** hold:
1. Exact name never appears in any `frontend/src` `.jsx/.tsx/.ts/.js/.html`.
2. No dynamic producer (no `` `root-${x}` ``/`:where` composition) yields it.
3. Zero consumers anywhere in the repo (backend, `shared/`, `medical/`, templates).

**Confirmed live (NOT removed) despite looking absent:** `is-*` state classes
(`is-due_today` etc. — planner does `` `is-${item.status}` ``), `xyndrome-logo-mark__image--*`
(`` `__image--${variant}` ``), all `study-*--*`/`student-*--*` BEM variants, `animate-*`
(Tailwind), `.ncv-item`/`.ncv-lightbox-*`.

## Phase 2 — THIS PASS (132 dead-token occurrences in grouped selectors)

Remove every remaining `.dead` token from selector lists, preserving live siblings.
- Inside `:where(L)` / `:is(L)`: drop the dead option(s); if the list empties, the whole
  segment matches nothing → drop the segment.
- Inside `:not(L)`: `:not(.dead)` is always-true → drop the `:not()`.
- Inside `:has(L)` or as a bare required part: dead → drop that comma-segment.
- If every comma-segment of a rule dies → remove the whole rule.

**Method:** Node + PostCSS (already installed) iterates rules; a paren-/forgiving-list-aware
processor edits `rule.selector` strings. Declarations and rule bodies are never edited (only
whole all-dead rules are dropped). No regex-on-raw-CSS, no new dependency.

## Phase 3 — DONE (non-class dead CSS, fix-or-delete only, visually inert)

Same discipline extended to the rest of the CSS:

- **`#__next`** (Next.js leftover; this is a Vite `#root` app) trimmed from `html, body, #__next` → `html, body` (segment-only; html/body keep all decls).
- **88 dead custom properties** (161 declarations incl. theme variants) removed — defined in `src`, never `var()`-used in ANY repo CSS, name absent from all repo code, not in tailwind config, no `@theme` blocks exist, no dynamically-built var names in JS. Abandoned `--ds-*` token layer, old `--pastel-*`/`--lpv2-*` landing palette, dupes.
- **4 rules dropped** once emptied (their entire bodies were dead props) + the 1 pre-existing empty rule.

All provably zero-render-effect. Method: PostCSS + same selector processor (`/tmp/css-phase3.cjs`), reading `/tmp/css-backup3` (post-Phase-2 snapshot). Verified: repo-wide dead props 0, dead keyframes/ids/empty-rules 0, **0 dangling `var()`** to removed props, html/body intact, all parse OK, dev server clean.

## Verification gates (must ALL pass, else revert)

1. PostCSS re-parse of every changed file: OK (no dangling commas / empty groups).
2. Brace balance unchanged per file.
3. **Live-class invariant:** `{classes in CSS before} − {classes after} === the 41 dead`
   — proves no live class was touched and no token introduced.
4. **Declaration invariant:** every surviving rule's declaration block is byte-identical;
   only declarations inside dropped all-dead rules disappear (each such rule logged).
5. Dead-token locator → **0** remaining occurrences.
6. Live Vite dev server: no errors, reload clean, stylesheets load.
